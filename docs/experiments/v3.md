# 步骤完整性 v3 实测报告

日期：2026-10-29。

## 结论

本轮完成参考样本、短句证据结构、逐动作关系、遗漏与条件检查、显式源复核修正及两条视频回归。Godot 原先漏掉的“重新启动场景”已经被模型保留，但模型生成的分支与依赖仍不合格。经 Codex 源复核后得到完整的10步讲解流程。

前端短句细分类没有达到自动使用要求，52/91处与冻结参考角色匹配，39处需要显式修正。因此 v3 作为检查和复核实验保留，既有 v2 概念流程继续保留；不把本轮细分类当作已验证的替代路线。

## 已确认的问题及处理

### 操作组容量无法容纳完整证据

旧版一个字段最多引用8个来源片段，Godot 必要流程从 SC0002 到 SC0010 需要9个片段，包含共享开启动词、设置路径、启动和条件分支。旧候选正好止于 SC0009。历史复现明确失败于缺少 SC0010；本轮保留了这份失败证明。

v3 为每个动作单独保存证据与关系，完整流程不再受单字段8条引用上限限制。12动作的合成回归通过；实际 Godot 的重新启动场景进入了模型输出。保留动作仍不等于关系正确。

### 有文字去向，仍可能没有可执行步骤

逐句覆盖只能证明材料没有从记录中消失。新检查分别核对动作是否进入流程、顺序是否合理、前序引用是否有效、条件是否传给分支的后续动作，以及“再/然后”是否暗藏漏步。

Godot 原始关系遗漏 SC0009 和 SC0010 的条件，程序产生两条 `branch_condition_not_carried` 告警。正式流程由独立、绑定原输出校验值的 Codex 修正记录形成，没有修改原始模型回执。

### 分类粒度过细会增加复核成本

程序完整保存了前端91个短句，但模型会把“注意标签别开太多”判为名称，把使用场景判为定义，把实际组件比较判为比喻。相邻上下文和类别约束没有充分解决这些问题。

不再继续以提示词微调掩盖本轮结果。当前结论是：细粒度单角色分类尚未证明有效，应保留完整语义句组，在统一任务与相同样本上比较分类方法后再决定路线。

### 辅助判断仍不可靠

辅助模型对前端角色错误中的38处、Godot角色错误中的2处仍返回 supported。程序检查、源复核和模型辅助判断分别记录。模型判断不能自行发布知识。
